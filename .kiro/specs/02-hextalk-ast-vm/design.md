# Technical Design Document: HexTalk Language, AST & Sandboxed VM

## 1. Scope & Shared Contracts
Modules: `ast.ts`, `astValidator.ts`, `parser.ts`, `vm.ts`, `fetchPolicy.ts` (all in `src/core/`, pure TypeScript). Grammar, AST types, VM semantics and fetch policy are defined once in `hexcard_design_spec.md` §4.1–4.3 and are not restated here.

## 2. Parser (`parser.ts`)
- **Lexer:** hand-written, line-aware. Tokens: keyword/identifier (case-folded), number, string, operator (`& && + - * / = <> < > <= >= ( ) ,`), newline, EOF. `--` comments are dropped. Every token carries `line`/`column`.
- **Statements:** recursive descent, one function per grammar rule.
- **Expressions:** precedence climbing with the levels of §4.1 (`or` < `and` < comparison < concatenation < additive < multiplicative < unary < primary). Comparison is non-associative: a second comparison operator at the same level is a syntax error.
- **Two-word operators:** `is not` and `down to` are recognised by one-token look-ahead.
- **Error recovery:** on an error inside a handler, record it, skip to the line `end <handlerName>`, continue with the next handler.
- **Printer:** `printHexTalk(ast)` walks the AST, applies the normalisation table of §4.2, and parenthesises a child expression only when its precedence is lower than the parent's (or equal on the right side of a left-associative operator).

## 3. AST Validator (`astValidator.ts`)
A Zod schema generated by hand from the §4.2 types, plus the extra rules of Requirement 3.2. Exported as `validateAst(unknown) -> { ok: true, ast } | { ok: false, reason }`.

## 4. VM (`vm.ts`)

~~~typescript
export type PendingEffect = { effect: VisualEffectType; speed: VisualEffectSpeed };

export interface HexHost {                       // injected; keeps the VM free of DOM/React/audio
  readField(ref: ResolvedFieldRef): string;
  applyRuntime(m: RuntimeMutation): void;        // spec 01 store write path
  resolveObject(t: HexObjectTarget, me: HexID): ResolvedObject; // throws HexScriptError if missing
  goToCard(target: HexCardTarget, effect: PendingEffect | null, ctx: DispatchContext): Promise<void>; // sends nested lifecycle messages
  playSound(voice: HexVoice, tempo: number, notes: string): void;
  showAnswer(prompt: string, buttons: string[]): Promise<string>;
  showAsk(prompt: string, defaultAnswer: string): Promise<string>;
  fetchJson(url: string, jsonPath?: string): Promise<{ ok: true; value: string } | { ok: false; reason: string }>;
  now(): { date: string; time: string; ticks: number; seconds: number; mouseH: number; mouseV: number };
}

export async function runHandler(
  handler: HexHandlerNode, params: (string | number)[], me: HexID,
  ctx: DispatchContext, host: HexHost
): Promise<"handled" | "passed">;
~~~

- `evalStatement` and `evalExpr` each call `ctx.tick()` first; `tick()` increments `ctx.stepCount`, throws `HexVmGasLimitError` above 10,000 and throws `HexAbortError` if `ctx.abortSignal.aborted`.
- Control flow uses internal sentinel results (`{ flow: "exitRepeat" | "nextRepeat" | "exitHandler" | "pass" }`) instead of exceptions, so gas accounting stays exact.
- `wait` awaits a timer promise that also rejects on abort.
- Locals: `Map<string, Value>` per handler call, with `it` pre-set to empty; globals: one `Map` owned by the runtime, never serialised.
- Errors carry `{ objectId, handler, line }` taken from the `loc` of the failing node.

## 5. Fetch Policy (`fetchPolicy.ts`)
Implements §4.3: URL check, `fetch` with `AbortController` (8 s), streamed body read with a 256 KB cap, `JSON.parse`, JSON-path walk (`Key { "." Key | "[" Digits "]" }`), result stringification. Used by the host's `fetchJson`.

## 6. Testing
- Golden tests: one source file per grammar rule, with expected AST JSON.
- Property tests (fast-check): random valid ASTs from an arbitrary generator -> `parse(print(A)) == A`; random parsed sources -> idempotent printing.
- VM: gas overflow in `repeat forever`, shared gas across nested `openCard`, `pass` semantics, `exit`/`next repeat`, value coercion table, property-validity errors, abort during `wait`.
- Fetch policy: blocked schemes, timeout, oversize body, non-JSON, path misses (mocked `fetch`).
